# 威胁模型（Threat Model）

读 README 只够你"会用"，这一页决定你"敢不敢在某些场景用"。一句话版本：

> **sandbox-ubuntu 给你的是"干净"，不是"隔离"。它默认不携带任何凭据；凭据是你主动放进去的，放进去就要为它的生命周期负责。**

## 1. 定位与不变量

- 本项目 = WSL2 发行版生命周期管理（导入 → 使用 → 校验式销毁）+ 云新机基线对齐。
- 不变量：
  1. 纯净模式下，**没有任何凭据、密钥、宿主文件系统访问、Windows 进程调用**进入沙箱（每次启动自检断言）。
  2. 身份模式下，token 只经内存（WSLENV）进入 guest，唯一的落盘点是 `/root/.git-credentials`（mode 600），随 vhdx 销毁。
  3. 日志永不包含 token（脚本只回显长度）。
  4. 销毁动作必须有复核结论：复查注册表项与 vhdx 确实消失，失败红字报警，绝不默认"应该没了"。

## 2. WSL2 不是安全边界

WSL2 是轻量虚拟机，但它的威胁模型**不包含对抗性隔离**：

- guest 内 root 与宿主之间的边界弱于完整 VM；已知/未来的内核或虚拟化层漏洞可能逃逸。
- 网络出口默认全通：guest 可以访问宿主能访问的一切（含局域网）。
- 结论：**它防的是"弄脏/弄坏我的环境"，不防"恶意代码针对我"。** 对抗性样本请用带快照的完整 VM 或专用分析机。

## 3. 两种模式的边界

| | 纯净模式（默认） | 身份模式 |
|---|---|---|
| 泄漏面 | 无凭据 | token 可被 guest 内任意 root 进程读取并外传 |
| 适合 | 一切常规测试；不完全信任的代码**也只建议在纯净模式跑** | 只跑你信任的代码（自己的仓库、自己的脚本） |
| -NoIdentity 的意义 | 默认已纯净 | token.txt 存在但本次临时不想带凭据 |

身份模式的铁律：**token 注入后，沙箱内任何代码都是持凭据代码。** 你从网上 curl 下来的安装脚本、别人发给你的仓库，一律视为"可能读走 token"。

## 4. 凭据生命周期（身份模式）

1. **创建**：GitHub → Settings → Developer settings → Fine-grained tokens。只勾选需要的仓库、Contents 只读、7~30 天有效期。与宿主机其他用途的 token 分开创建。
2. **传输**：宿主读 `token.txt` → `WSLENV=GHTOKEN/u`（仅 Win32→WSL 方向）→ guest 环境变量 → 写入 `.git-credentials` 后立即 unset。
3. **落盘**：仅 `/root/.git-credentials`（600）与 `/root/.gitconfig`，位于运行期 vhdx 内。
4. **销毁**：`wsl --unregister` 删除整个 vhdx；脚本复核后报告。token.txt 本身留在宿主，不受影响。
5. **泄漏应对**：GitHub 上直接 revoke；作用域已限死在勾选仓库 + 只读，损失可控。

宿主侧 `token.txt` 是明文文件：确保它不被同步盘/备份工具带出去，用完及时删除（本项目 .gitignore 已排除，但 gitignore 不是保险箱）。

## 5. 供应链

- rootfs 下载 URL 与 SHA256 固定在 `versions.json`，下载后强校验，不匹配即中止。改动这两个字段 = 改变你信任的机器镜像，请 review diff。
- 构建产物母版附带 `.sha256`，每次启动导入前再校验一次：防止磁盘损坏或母版被无意改动后带病上线。
- 母版构建过程本身可复现：`build-base.ps1 -Version <id> -Force` 从官方 rootfs 重建，产物哈希应稳定（apt 包版本随镜像点版本漂移属正常）。

## 6. 清理保证与已知失效模式

- 正常退出（`exit`）：shell 返回后执行校验式清理，复核通过才报成功。
- **点窗口 X / 强杀终端**：清理代码不会执行，vhdx 残留——这是结构性限制（Windows 不给被杀进程跑 finally 的机会）。缓解：下次启动检测残留并自动清理；`cleanup.cmd` 随时手动兜底。残留期间的凭据仍在 vhdx 里，清理前请不要把机器交给不可信的人使用。
- 清理失败（文件占用等）：红字报警 + 重试 3 次 + 仍失败则如实报错，不谎报。

## 7. 简明守则

1. 跑不完全信任的东西：纯净模式，或者别用本项目。
2. token 最小权限、短有效期、用完 revoke。
3. 看到 `[FAIL]` 或红字，先处理再继续——所有失败信息都被设计为"可以安全忽略的只有绿色"。
